# 00_PROJECT_RULES.md
# Champion Tour Design Documents
Version: 1.0

## Purpose
This document defines the non-negotiable rules of the Champion Tour project.
Every future implementation must follow this document.

---

# 1. Vision

Champion Tour is an original merge game where the player restores and expands a modern sports academy.

The first academy is Football Academy.

The objective is to create a premium mobile game inspired by the progression feeling of merge games, while all artwork, assets, UI, economy and identity remain original.

---

# 2. Project Goals

- Premium visual quality
- Relaxing gameplay
- Long-term progression
- Fair economy
- Highly satisfying merge experience
- Professional codebase suitable for Unity migration

---

# 3. Locked Development Order

The order below must never change unless explicitly approved.

1. Football Academy
2. Core Merge Gameplay
3. Orders
4. Producer Progression
5. Academy Renovation
6. Economy Balancing

# 4. Producer Rules

Producer Levels:

Football Academy Rules

- Four producer families exist together on the board.
- Ball Basket, Equipment Locker, Training Cart and Trophy Cabinet are permanent.
- Each producer generates only its documented chain.
- Every producer uses Energy and has independent charges/cooldown.
- Producer progression remains shared across the active academy.

Rewards

Lv2 = 1 Diamond
Lv3 = 1 Diamond
Lv4 = 2 Diamonds
Lv5 = 2 Diamonds
Lv6 = 3 Diamonds

---

# 6. Orders

Orders are the primary progression mechanic.

Orders grant:

- Coins
- XP

Producer progression must depend on completed orders rather than elapsed time.

---

# 7. Merge Rules

- Drag & Drop merge
- Double-click merge
- Merge only identical items
- Merge feedback through animation
- No congratulation text such as "Harika!"

---

# 8. UI Principles

- Rounded corners
- Soft shadows
- Pastel color palette
- Large item preview
- Consistent spacing
- No debug labels in production

---

# 9. Art Direction

Cute
Warm
Premium
Readable
Modern

Avoid:
- Photorealism
- Harsh colors
- Generic placeholder assets

---

# 10. Coding Rules

Codex must:

- Read all design documents before coding.
- Preserve existing gameplay.
- Never invent mechanics.
- Never remove working systems without explicit instruction.
- Explain implementation plan before coding.
- Summarize modified files after implementation.
